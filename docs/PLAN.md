# MasterDriver 跨境師傅幫：完整規劃

> 版本：2026-10-13 ｜ 狀態：草案，待拍板 ｜ 口號：有單就派，有空就接 ｜ 名稱待商標及網域查核

## 一、定位

**一句話：**MasterDriver 跨境師傅幫（簡稱「師傅幫」）是一個獨立、免費、可以直接在微信群和 WhatsApp 群裡使用的派單接單工具。任何規模的司機都能用，不改變他們在群裡的習慣，同時幫他們經營自己的客源。

### 品牌定位

| 品牌 | 給誰 | 定位 |
|---|---|---|
| MasterDriver 跨境師傅幫 | 司機（個人、小團隊） | 免費接單派單工具 |
| MasterTravel | 公司、車隊 | 自己品牌的完整運營系統 |

**一句話講清楚升級路徑：**司機用 MasterDriver，做大了就用 MasterTravel 開公司。

**命名理由：**Master 對應「師傅」，是司機的身份；「跨境」標示核心市場；「幫」代表師傅之間互相派單、互相接單。

### 為什麼要做

- **行業現況：**乘客從 FB、小紅書、抖音來；單在大量的微信群和 WhatsApp 群裡流轉；派單和搶單全靠打字、回覆「我接」。
- **Master Travel 的難處：**Master Travel 是「一家公司一套、帶自己品牌」的完整運營系統，透過「預約演示」銷售。對習慣在群裡打字的市場來說，一步跨過去太重。
- **做法：**把 Master Travel 派單功能中最輕的一段（連結派單、搶單、外部司機不用註冊、乘客確認）簡化成獨立工具，讓它跟著單在群裡流傳。

### 要達成的四件事

1. 讓 Master Travel 進入市場：每一條連結、每一張推廣圖都在曝光。
2. 讓市場養成「用連結派單和接單」的習慣。
3. 找出規模在成長的團隊和公司，引導他們用 Master Travel 搭建自己的運營系統。
4. 用訂閱保留收費的主動權。

**唯一的終極標準：**帶來多少 Master Travel 客戶。訂閱收入是次要的。

## 二、設計紅線

1. **不改變習慣：**用戶照樣在群裡發單、聊天、搶單，工具只是多一條連結。任何要用戶離開群、先學操作、先填一堆資料的設計，都不做。
2. **在微信內完整可用：**派單、搶單、乘客確認都能在微信內建瀏覽器裡走完全程，WhatsApp 也一樣。
3. **任何規模都能用：**一個人就能發單，不用先建立公司或池。
4. **Master Travel 完全不動：**兩邊沒有程式或資料上的連接，只靠人工銷售銜接。
5. **不做 Master Travel 的核心：**自動報價、收款、結算、司機審核、自有品牌的乘客端、會員積分，任何一級都不做。
6. **幫司機經營自己的客源，不做我們的乘客平台：**不做乘客叫車平台；平台不分配乘客、不定價、不收款。所有獲客功能都是「讓司機自己的帖子和頁面更好」。「司機名錄」（乘客按路線、車型、語言自行挑選司機，直接聯絡或預約）保留空間但先不做，第四階段評估。

## 三、角色

| 角色 | 說明 |
|---|---|
| 司機（用戶） | 驗證手機後，同時可以發單和接單。一個人的司機也能把自己接不了的單轉出去 |
| 團隊／公司 | 可選的升級，需要固定成員、副手、品牌化時才開 |
| 乘客 | 不用登入。可以打開確認連結按「確認」，或透過司機的名片頁預約 |
| 平台（我們） | 後台管理收費控制、廣告、潛在客戶名單 |

## 四、核心流程

### 發單

```
在工具發單（或「複製上一張」再修改）
→ 拿到派單連結、乘客確認連結，以及一段排好格式的文字
→ 一鍵複製，貼到任意多個微信群或 WhatsApp 群
→ 把乘客確認連結傳給乘客
```

### 接單

```
在群裡看到單 → 點連結 → 第一次驗證手機、填基本資料（之後都記住）
→ 按「搶單」，先到先得
→ 搶到才看得到乘客聯絡方式；所有群打開同一條連結，都會顯示「已被接走」
```

### 收尾

```
一鍵複製「已派出：XX 司機／車牌」→ 貼回群裡
乘客按確認 → 發單者看到確認時間
司機在「我的接單」、發單者在「我的派單」查看所有紀錄
```

### 空車回程（反方向的派單）

```
司機發布空車（時間、方向、車型、座位）→ 貼到群裡
→ 有單的人點連結，直接把單派給他 → 沿用同一套確認流程
```

### 獲客（幫司機經營自己的客源）

```
產生推廣素材（路線價格圖、二維碼海報）→ 發到 FB／小紅書／抖音
→ 乘客掃描二維碼 → 看到司機名片頁 → 送出預約
→ 司機確認、報價 → 成為一張單（自己做，或發到群裡派出）
```

### 搶單範圍

- **個人用戶：**有連結的驗證司機都可以搶，等於在群裡回覆「我接」。發單者可以查看搶單司機的資料，有疑慮時可以取消或改派。
- **團隊（付費）：**可以設定「只限團隊成員」。

## 五、功能範圍

**單的欄位：**日期時間、出發地、目的地、途經點（全部純文字，不用地圖）、人數、行李、車型、價格（自行填寫）、備註、乘客聯絡方式（搶到才顯示）。

**平台服務費（抽水，2026-10-13 決定）：**
- 只向**派單者**收，每單**固定金額**，從**預充值點數**扣；接單司機永遠不收；
- 平台後台可開關與設定金額，預設關閉；團隊、公司訂閱與上線全站免費期免收；
- **發單時扣點數，取消全額退回**：點數不夠就不能發單（提示充值或訂閱），但永遠不會讓司機因派單者點數不足而搶不到單；
- 點數用 Stripe 或 AlipayHK 購買（第三階段），在此之前可由後台人工充值；
- 屬「使用工具的服務費」，不按車費比例抽成，平台不經手車費；上線前請律師確認性質。

**兩個價格（2026-10-13 決定）：**派單司機分別填寫**司機價**與**乘客價**，自己看得到差價：
- 司機價：貼到群裡、搶單頁顯示，所有司機都看得到；有人接單後鎖定，不能再改；
- 乘客價：派單司機決定是否在乘客確認頁和傳給乘客的訊息中顯示；
- 差價：只有派單司機看得到；接單司機永遠看不到乘客價，乘客永遠看不到司機價。

**司機資料（第一次填）：**姓名、車牌（港、澳、內地，可以只填一部分）、車型座位、車色。不收證件照片。

| 第一版 | 第二階段 | 第四階段評估 | 永遠不做 |
|---|---|---|---|
| 手機驗證碼登入（+852、+86） | 社群推廣素材 | 公開單廣場（由發單者自願勾選）；司機名錄（司機自願加入） | 自動報價、路線定價 |
| 發單、複製上一張、取消、改派 | 司機名片頁 + 預約頁 | 內地付款方式補強 | 收款、訂金、退款 |

| 一鍵複製（微信）、一鍵分享（WhatsApp） | 貼上群組文字自動拆單 | MasterDriver 自己的微信小程序、App | 替司機做自有品牌的小程序、App |
| 乘客確認連結（要按確認） | 團隊：固定成員、副手、只限成員 | | 會員、積分、錢包 |

| 收費控制機制（第一天就要有） | | | 平台替司機分配乘客 |
| 平台後台：用戶、單量、潛在客戶排名 | | | 公開給乘客的評價和排名 |

### 第二階段功能要點

- **社群推廣素材：**填入路線、車型、價格，產生適合小紅書、抖音、FB 的圖片，附上通往名片頁的二維碼。二維碼用來避開平台對外部連結的限制。
- **名片頁 + 預約頁：**車輛照片、常走路線、語言、服務地區、完成單數。完成單數只計算工具裡真實完成的單，不能自行填寫。乘客預約後，先由司機確認、報價，不直接成立訂單，因為跨境價格會隨時間、口岸、人數改變。
- **自動拆單：**用試點時收集到的真實群組文字設計辨識規則。

**為什麼獲客功能不放第一版？**第一版要牢牢守住「群組習慣」這個核心，證明大家願意用連結派單和接單。獲客功能需要乘客改變行為，等試點證明核心可行後再加入。

## 六、訂閱與收費控制

### 三條原則

1. 接單、乘客確認、空車廣播永遠免費，只向發單和經營的一方收費。
2. 以「團隊／公司」為收費單位，不按人頭收費。
3. 任何一級都不做 Master Travel 的核心功能。

### 分級（工具內三級，第四級是 Master Travel）

| 功能 | 個人（免費） | 團隊（付費） | 公司（付費） |
|---|---|---|---|
| 發單、接單、乘客確認、一單多群 | ✔ | ✔ | ✔ |
| 空車回程廣播 | ✔ | ✔ | ✔ |
| 每月發單數 | 有上限 | 較高 | 不限 |
| 歷史保存 | 短期 | 長期 | 長期 |
| 固定成員、副手、只限成員搶單 | — | ✔ | ✔ |
| 報名後挑選、直接指派 | — | ✔ | ✔ |
| 自動拆單 | 少量試用 | ✔ | ✔ |
| 統計 | — | 基本 | 完整、可匯出 |
| 社群推廣素材 | 基本範本，有工具標記 | 去除標記、自訂 Logo | 更多範本、團隊統一品牌 |
| 名片頁 + 預約頁 | 1 頁，有工具標記 | 品牌化 | 多頁、來源追蹤 |
| 乘客確認單去除工具標記 | — | ✔ | ✔ |

所有額度和功能歸屬都可以在後台調整，表中的數字只是示意。

### 控制機制（後台操作，不需要改程式）

| 層級 | 用途 |
|---|---|
| 1. 功能目錄 | 列出所有可收費的功能（開關型或額度型） |
| 2. 方案設定 | 每一級包含哪些功能、額度多少 |
| 3. 全站免費期 | 設定開始和結束時間，期間所有人享有指定級別 |
| 4. 單一功能限時免費 | 例如「自動拆單本月免費」 |
| 5. 個別用戶覆蓋 | 試用、贈送、延長，例如 Master Travel 客戶贈送公司級 |

- **判斷順序：**個別覆蓋 → 單一功能限免 → 全站免費期 → 訂閱方案 → 免費預設。
- **所有判斷都在後端做**，前端只負責顯示。
- 轉為收費前自動通知，並設寬限期；每次變更都留下紀錄。

### 收費節奏

1. 上線時開啟全站免費期，所有功能都開放；
2. 用使用數據決定哪些功能收費；
3. 提前一個月公告，早期用戶獲得優惠；
4. **訂閱收費使用 Stripe**（2026-10-13 決定），只在網頁購買：
   - 使用 Stripe Checkout 付款頁與 Customer Portal（用戶自行管理訂閱、更換信用卡、取消），本專案不經手卡號；
   - 以 Stripe webhook 為付款結果的唯一依據，同步到本專案的訂閱紀錄；**能不能用功能仍由本專案的權益模組判斷**，全站免費期、限時免費、個別贈送都在本專案控制，不用 Stripe 的試用期取代；
   - 使用 MasterDriver 獨立的 Stripe 帳戶或獨立的產品與價格，與 Master Travel 的收款分開；金鑰與 webhook 簽章密鑰只放雲端金鑰管理服務；
   - **內地用戶多數沒有 Visa／Mastercard**：信用卡適合自動續訂；支付寶、微信支付一般不支援自動續訂，預計改為「一次付一個月或一年、到期提醒續費」。Stripe 對香港商戶開放的付款方式與續訂支援要在接入前確認；
   - **加上 AlipayHK**（2026-10-13 決定）：預計以「一次付一個月或一年、到期提醒續費」方式收費。接入途徑二選一，接入前確認：
     - 經 Stripe：Stripe 文件只列出單一的「Alipay」付款方式（支援港幣），沒有明確提到 AlipayHK 錢包；Alipay 的自動續訂仍屬需申請的預覽功能；
     - 直接接 AlipayHK：參考 Master Travel 已有的 AlipayHK 收款設定做法（`docs/REUSE.md` 第 B 類），使用 MasterDriver 獨立的商戶設定；
   - 無論哪個途徑，付款結果都同步到本專案同一套訂閱紀錄，功能開關仍由本專案的權益模組判斷；
   - 必要時保留人工開通（例如轉數快），作為補充。

## 七、升級到 Master Travel 的路徑

**梯子：**個人 → 團隊 → 公司 → Master Travel（自己品牌的完整運營系統）

### 工具內的觸發點（在用戶真的需要時才出現）

| 用戶遇到的需求 | 提示 |
|---|---|
| 名片頁的預約越來越多 | 想要乘客直接下載你自己品牌的小程序和 App？ |
| 每張單都要手動報價 | Master Travel 可以按路線和距離自動報價 |
| 要收訂金、收款 | Master Travel 支援香港和內地多種收款方式 |
| 要和司機算錢 | Master Travel 有司機結算和財務中心 |

- **名片頁是通往 Master Travel 最自然的一步：**它就是「自有品牌乘客端」的縮小版。
- **入口：**升級提示和廣告欄位一律連到品牌網站的「預約演示」，以及微信、WhatsApp 諮詢。這些都已經存在，Master Travel 不需要任何修改。
- **廣告位置：**放在司機和發單者看到的頁面，例如搶單頁、我的接單、我的派單、後台。乘客確認頁和名片頁不放 Master Travel 廣告，免費版只顯示一個小小的工具標記，避免讓司機在乘客面前尷尬。
- **銷售：**後台按單量、成員數、活躍度、成長速度、名片頁預約量排出潛在客戶，由銷售人員主動聯絡。客戶升級時，從工具匯出資料（Excel／CSV），由我們的團隊協助導入他們的 Master Travel。

## 八、技術方向

- **完全獨立：**獨立倉庫、資料庫、網域、部署。Master Travel 的程式只用來參考邏輯，不共用。
- **前端：**第一版是輕量網頁，不用 Flutter Web。目標是內地網絡在微信內 2 到 3 秒打開。
- **為 App 和小程序預留：**之後會考慮 MasterDriver 自己的 App 和微信小程序。因此：
  - 後端採 **API 優先**，所有商業規則都在 API，網頁、小程序、App 共用同一套 API；
  - **不使用 uni-app**。網頁用 **Vue 3 + Vite**；小程序之後用**原生小程序**寫（頁面少，最穩定，不依賴嵌入網頁，因為嵌入需要備案網域）；App 先用 **Capacitor** 包裝網頁加上推播，需要更原生時再評估 Flutter；
  - 各端不共用前端程式，靠 API 與 `shared/` 契約（狀態、欄位、驗證規則）保持一致，分享文字一律由後端產生；
  - 登入以手機號為主帳號，日後小程序可加微信登入並綁定同一手機號；
  - 單和連結的格式要能同時開啟網頁和小程序。
- **小程序和 App 的價值：**小程序卡片可以直接分享到微信群，比文字加連結更醒目，也更貼近群組習慣；App 可以推播新單和空車通知。
- **小程序網域（2026-10-13 查證，部分證實）：**以香港公司（境外主體）上架，微信開放社區的答覆指境外主體小程序目前無需 ICP 備案，境外註冊的網域也無法備案，因此**後端 API 網域預計可以不備案**；但微信官方開發文件仍寫「服務器域名必須經過 ICP 備案」且未列豁免，社區答覆也提醒未備案連結可能不穩定。**嵌入網頁（web-view 業務網域）仍需備案**，所以小程序維持用原生寫。最可靠的證據是 Master Travel 現有小程序的實際設定，上架前再以微信公眾平台當時的規則確認。
- **App 上架：**香港和內地應用商店的上架要求不同，上架前確認。
- **注意區分：**MasterDriver **自己的** App 和小程序可以做；**替司機做自有品牌**的小程序和 App 屬於 Master Travel，永遠不做。
- **不依賴內地被封鎖的服務：**例如 Google 地圖、Google 字型、reCAPTCHA、Firebase。
- **登入：**手機驗證碼，不用微信登入。登入狀態要耐得住微信清除網頁資料。
- **主機和網域：**放香港，不備案（現有伺服器已確認微信內可以打開）。使用獨立網域，不用 Master Travel 的子網域，另外準備備用網域。
- **搶單一致性：**一單多群同時搶時，後端用條件更新確保只有一人成功，並留下每一次搶單紀錄。
- **分享：**不依賴微信分享卡片，複製的文字本身要把單講清楚；設好 WhatsApp 的連結預覽。微信內不顯示「跳到 WhatsApp」；下載功能改為提示「在瀏覽器打開」；不用第三方短網址。
- **推廣素材：**在伺服器端產生圖片，確保在微信內也能長按儲存。
- **成本控制：**簡訊驗證碼要限制頻率，後台看得到每月用量。

**SEO 的固定保護（後台不能改）：**
- 搶單頁（`/o/`）、乘客確認頁（`/c/`）、司機端與後台一律 `noindex`，不放進 sitemap：這些頁面含行程資訊，不應被搜尋引擎收錄；

**金鑰的安全要求：**
- 私密金鑰、簽章密鑰、商戶私鑰以 Google Cloud KMS 加密後才存入資料庫，不以明文儲存；
- 只能寫入、不能讀回：後台只顯示末幾碼，API 永遠不把金鑰回傳給前端；留空代表沿用已儲存的值；
- 只有超級管理員可以修改；每次修改都寫入操作紀錄（不記錄金鑰內容）；
- 測試與正式環境分開儲存；切換或更新正式環境金鑰時要再次確認；
- 儲存前先驗證格式與環境是否相符，並提供連線測試。

## 十一、風險與對策

| 風險 | 對策 |
|---|---|
| 連結被檢舉、被微信封鎖 | 獨立網域、備用網域、頁面保持乾淨，不做誘導分享 |
| +86 簡訊收不到 | 第 0 階段實測，必要時多通道；驗證一次長期記住 |
| 冷啟動沒人用 | 從熟悉的司機和團隊開始，整群帶入 |
| 陌生司機搶單的信任問題 | 搶到前不公開乘客資料；發單者可以查看司機資料、取消或改派 |
| 小紅書、抖音判定為導流而限流 | 素材以二維碼圖片為主，帖子文字裡不放連結；試點時觀察 |
| 名片頁內容不實 | 完成單數由系統計算；提供檢舉入口；不公開評價排名 |
| 被誤認為乘客平台、背負平台責任 | 頁面清楚標示「由司機自行提供服務」 |
| 與 Master Travel 現有司機端「Master App Driver」名稱相近，造成混淆 | 對外清楚說明兩者分工；Master Travel 司機端名稱由它自己日後排期處理，不因新平台而修改 |
| 「跨境」屬描述性用詞，單獨難以註冊 | 以「跨境師傅幫」全名和 MasterDriver 一併申請商標；定名前查核同名品牌 |
| 工具太好用，沒人升級 | 嚴守「永遠不做」清單；追蹤升級詢問比例 |
| App 和小程序內的訂閱購買受平台規則限制（應用內購買、抽成、虛擬支付限制） | 訂閱只在網頁購買，App 和小程序內不放購買入口；上架前確認 Apple、Google、微信的最新規則 |
| 內地用戶沒有國際信用卡，無法訂閱 | 接入前確認 Stripe 對香港商戶的支付寶、微信支付支援；不支援自動續訂時改為一次付費加到期提醒；保留人工開通 |
| Stripe webhook 遺失或重複 | 以事件編號去重；定期與 Stripe 對帳；權益模組設寬限期，避免付款延遲時立即停用 |
| 免費導致成本失控 | 簡訊限頻、額度上限、後台監控用量 |
| 兩地個資和載客撮合合規 | 上線前請專業人士審閱 |

## 十二、已確認的決定
