# 拼車（試做分支）

> 本文件只在分支 `claude/group-purchase-feature-423f8a`。拼車不一定採用；決定採用、合併回 `main` 時，再把以下內容併入 `docs/DECISIONS.md`、`docs/PLAN.md` 與 `docs/DEVELOPMENT.md`，並刪除本文件。

## 來由

使用者 2026-10-15 要求做拼單功能，確認是拼車（一部車載幾組互不認識的乘客）；以顧問方式規劃，對比 BlaBlaCar、滴滴順風車、UberX Share、永東拼車與微信接龍後，使用者表示「BlaBlaCar 模式感覺不錯」，並指示「按方案實作」、「先不考慮法律問題，平台沒有幫司機拉客」。

## 方案（BlaBlaCar 式，平台不配對）

司機開一趟拼車，得到一條連結，自己發給乘客；乘客打開連結報位；湊夠或截止後，司機自己開，或把整車派出去讓別的司機接。

守住紅線 6 的三點：連結只由司機自己發；平台不列出、不搜尋、不推薦任何拼車（拼車不進接單池；成單派出去之後，那張單照一般單的規則由出單者決定放不放接單池）；每位價錢由司機自己填。

| 從 BlaBlaCar 學的 | 做法 |
|---|---|
| 每趟選自動確認或司機確認 | 預設司機確認；司機確認的報位 2 小時（或到報位截止，取較早者）沒回覆就失效，座位放回去 |
| 等待確認的報位先佔位 | 是，避免司機確認超過座位 |
| 座位即時更新、只開放真有的座位 | 座位數不能超過司機資料的座位減 1（司機自己一個位），司機資料沒填座位不能開拼車 |
| 確認後才交換電話 | 乘客確認後才看到司機電話；司機在報位確認後才看到乘客電話 |
| 等候與沒出現 | 每組「已到上車點」後過了等候時間（預設 15 分鐘，司機可改）才能按「乘客沒出現」 |

| 改了再學 | 做法 |
|---|---|
| 取消退款規則 | 司機選填自己的取消規則文字，報位頁與乘客連結都顯示；平台不執行、不經手錢，只記下乘客取消的時間 |
| 平台建議價 | 不做，價錢一律由司機填 |

不學：公開搜尋行程、平台代收款、只能分攤成本、禁止替別人開（我們保留派出去）、禁止平台外聯絡、互評分。

## 流程

```
司機開拼車（時間、起終點、上車點選項、座位、每位價錢、最少成行人數、
          每位行李、取消規則、報位截止、確認方式、等候時間、收款方式）
  → 司機複製乘客版文字和連結（/r/{code}），自己發給乘客
  → 乘客報位（不用登入）→ 得到自己的連結（/s/{code}）
  → 招募中 → 已成行（確認人數到最少成行人數）
  → 截止（人滿不會自動截止；司機按「停止報位」或到了截止時間）
      ├─ 自己開：變成一張「這單我自己做」的拼車單
      └─ 派出去：變成一張拼車單，照一般單發到群裡或放進接單池讓人搶
  任何時候（成單前）：司機可以取消整趟
```

- 截止時還不夠人，系統不自動取消；司機可以照樣出發、延後截止時間（改了截止時間就重新開放報位）或取消。
- 截止後還有等待確認的報位，要先確認或婉拒才能成單。
- 改了出發時間或每位價錢，已報位的乘客都要在自己的連結上按「接受新的安排」；未接受的照樣佔位，但不算進成行人數。
- 成單後乘客連結上的司機換成接單司機（派出去且有人接時），不用乘客重新確認。

## 成單後的拼車單

- 一張單、一位司機、幾組乘客；單的人數和行李是各組加總；出單價整張單一個（派出去時由開拼車的司機填）；沒有乘客價，各組的價錢是每位價錢乘人數。
- 群文字開頭為「【有單・拼車】」，列出上車點、組數、總人數、總行李、車型與出單價，不列乘客資料。
- 「已出發」整張單按一次；每組各自「已到上車點」「已上車」「乘客沒出現」「已下車」。第一組到了上車點，整張單記為已到上車點；每組都已上車或沒出現，整張單記為乘客已上車。
- 接單司機看到各組的稱呼、上下車點、人數；電話照「乘客電話顯示時間」。
- 「已收款」按組各自標記；收款方式在拼車頁開關，乘客連結顯示每位價錢乘人數。
- 成單後不能用「修改行程」（行程由報位決定）；要改，取消後重開拼車。成單後司機仍可取消某組乘客，接單司機會收到「出單者改了你接的行程」並按「知道了」。
- 取消拼車單即取消整趟拼車；改派或接單司機取消接單時，各組的行程進度一併清除。

## 收費

開拼車、乘客報位都免費。成單（自己開或派出去）時照一般單計算：用一張出單額度，平台服務費開啟時扣一次，取消退回。

說明：規劃時寫「自己開免費，和『這單我自己做』的現行規則一致」，但現行「這單我自己做」其實照樣用額度、收服務費（`OrdersService.create`），所以實作改為照現行規則。是否要讓自己開的拼車免收，待決定。

## 通知（歸在「名片頁預約與拼車」這組開關）

- 有人報位（自動確認時是「有人報位了」，司機確認時是「有人報位，等你確認」）
- 乘客取消報位
- 拼車成行（確認人數第一次達到最少成行人數）
- 報位已截止（到了截止時間，下次讀通知時寫入，和「還沒人接」一樣）

乘客沒有站內通知；狀態只顯示在乘客自己的連結上，司機另外在微信或 WhatsApp 通知。

## 防濫用

- 同一個電話在同一趟拼車只能有一個有效報位。
- 同一網絡位置每天的報位數，沿用後台「防濫用設定」的「同一 IP 每天預約數」上限（和名片頁預約分開計算）。

## 頁面與 API

| 頁面 | 用途 |
|---|---|
| `/app/carpools` | 我開的拼車 |
| `/app/carpools/new` | 開拼車 |
| `/app/carpools/:id` | 管理一趟拼車：乘客版文字、報位、修改、停止報位、成單、取消 |
| `/r/:code` | 給乘客的拼車連結：行程、剩幾位、報位 |
| `/s/:code` | 乘客自己的報位連結：狀態、司機、行程進度、收款方式、取消 |

| 方法與路徑 | 登入 | 用途 |
|---|---|---|
| `POST /api/carpools` | 要 | 開拼車（要先有司機資料與座位數） |
| `GET /api/carpools` | 要 | 我開的拼車 |
| `GET /api/carpools/unread` | 要 | 等待確認的新報位數 |
| `GET /api/carpools/:id` | 要 | 一趟拼車與它的報位；打開即標為已讀 |
| `PATCH /api/carpools/:id` | 要 | 修改（成單前）；改時間或價錢要乘客重新接受；改截止時間可重新開放 |
| `POST /api/carpools/:id/close` | 要 | 停止報位 |
| `POST /api/carpools/:id/cancel` | 要 | 取消整趟（成單前；成單後取消那張單） |
| `POST /api/carpools/:id/start` | 要 | 成單：`{ mode: 'SELF' }` 自己開，`{ mode: 'DISPATCH', driverPrice, vehicleType, inPool }` 派出去 |
| `POST /api/carpools/:id/seats/:seatId/confirm\|decline\|remove` | 要 | 確認、婉拒、取消某個報位 |
| `POST /api/orders/:id/carpool-seats/:seatId/progress` | 要 | 接單司機回報某組 `ARRIVED`、`PICKED_UP`、`NO_SHOW`、`DROPPED_OFF` |
| `PATCH /api/orders/:id/carpool-seats/:seatId/payment` | 要 | 出單者標記某組已收款 |
| `GET /api/public/carpools/:code` | — | 拼車連結 |
| `POST /api/public/carpools/:code/seats` | — | 報位 |
| `GET /api/public/carpool-seats/:code` | — | 乘客自己的報位 |
| `POST /api/public/carpool-seats/:code/cancel\|reconfirm` | — | 取消報位、接受新的安排 |
| `GET /api/s/:code/driver-photos/:id`、`GET /api/s/:code/payment-methods/:id/qr` | — | 乘客連結上的車輛照片與收款碼 |
| `GET /api/public/carpools/:code/photos/:id` | — | 拼車連結上開拼車司機的車輛照片 |

資料表：`Carpool`（一趟拼車，成單後 `orderId` 指向那張單）、`CarpoolSeat`（一組乘客的報位與行程進度）；`Notification` 多了 `carpoolId`。

## 本機試用

這個分支的資料表只套用在獨立的本機資料庫，不動 `main` 用的開發資料庫：根目錄 `.env`（不提交）把 `DATABASE_URL`、`TEST_DATABASE_URL` 指向 `master_driver_carpool`、`master_driver_carpool_test`，API 用 3030 埠、`PUBLIC_BASE_URL` 用 `http://localhost:5190`。`.env` 是從主工作樹的 `.env` 複製後改的，不在 Git 裡。

## 本分支另含的修正（與拼車無關）

驗證拼車時，在全新資料庫上發現首次載入有兩個 500：兩個請求同時建立一般設定那一列，其中一個撞到唯一鍵（P2002）。修正為輸的一方再做一次就會讀到那一列（`backend/src/common/first-write.ts`），套用在 `backend/src/site/site.service.ts` 的一般設定、SEO、Logo 與廣告每日統計，並在 `site.db-test.ts` 加了同時寫入的測試。這個修正一樣只在本分支、未提交；要不要單獨放到 `main`，等使用者決定。
